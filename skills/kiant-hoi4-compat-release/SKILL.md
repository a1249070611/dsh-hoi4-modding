# 兼容性与发布

## 加载顺序

同一路径下多个 mod 都定义了同名文件或同名 id 时，**后加载的覆盖先加载的**。加载顺序由启动器的 playset 决定（玩家可拖拽排序），mod 自身只能通过 `dependencies` 提建议，不能强制。

这意味着：

- 你不能假设自己最后加载
- 想做兼容补丁，就得让玩家把它排在你所补的 mod 之后
- 在描述里写清"请放在 XXX 之后加载"，并在 `dependencies` 里声明依赖

```
dependencies={
	"The Road to 56"
}
```

## 覆盖原版文件的两种策略

### 策略 A：整文件覆盖

复制原版文件到 mod 的同名路径，然后改动。

- 优点：简单直接，改哪里看得见
- 缺点：原版更新后你的版本变旧，新内容全部丢失，且不会报错
- 适用：必须大改结构的场景（比如重写某个国家的整棵国策树）

### 策略 B：追加式

不改原版文件，只新建文件加自己的内容。

- 优点：原版更新不影响你，兼容性最好
- 缺点：有些东西无法通过追加实现（比如修改原版某个已存在的国策）
- 适用：绝大多数场景

**默认选 B。** 只有当 B 确实做不到时才转到 A，并在文档里明确标注"覆盖了原版文件 X，版本更新后需人工同步"。

### 绝对不要用的：replace_path

```
replace_path="common/ideas"
```

整目录替换，原版该目录下所有文件不再加载。它会：

- 让原版所有国家精神消失
- 让任何想往该目录追加内容的 submod 彻底失效
- 让兼容补丁无从下手

只有 total conversion 才考虑。用过之后你的 mod 基本退出"可组合"生态。

## submod 设计

想让别人能在你的 mod 上加内容，就要留出扩展点：

1. **不要用 `replace_path`** —— 根本前提
2. **内容分散到独立文件**，别把所有国策塞一个文件——submod 覆盖单文件时影响面小
3. **提供 `scripted_effect` / `scripted_trigger` 钩子**，让 submod 调用而不是复制你的逻辑
4. **id 加命名空间前缀**，降低冲突概率
5. **文档写清哪些文件是"稳定接口"**，哪些是内部实现

## 游戏版本升级应对

大版本更新（如 1.18 → 1.19）后典型情况：

1. 启动器把 `supported_version` 不匹配的 mod 标为过期，但仍可强制启用
2. 被你覆盖的原版文件已变，你的版本缺新内容 → 表现为"新 DLC 内容不见了"
3. 部分 effect / trigger 改名或移除 → `error.log` 出现 `invalid` / `could not find`
4. GUI 文件结构变动 → 界面错位

应对顺序：

```
1. 在干净存档里跑一遍，kiant_hoi4_analyze_error_log 看新增错误
2. 对照更新日志找被改动的系统
3. 逐个更新被覆盖的原版文件（从新版游戏目录重新复制再改）
4. 只改 supported_version 不改代码 = 自欺欺人，别这么干
```

## 创意工坊上传

流程：

1. 启动器里启用你的 mod，进游戏一次（确保 `descriptor.mod` 被正确读取）
2. 退出到启动器 → 模组 → 你的 mod → 上传
3. 首次上传后，启动器会往 `descriptor.mod` 写入 `remote_file_id="<id>"`
4. 之后更新直接再次上传覆盖

**关键点**：上传读的是 `descriptor.mod`，不是外层 `.mod`。两个文件的 `name` 和 `version` 要一致，否则工坊页面显示和启动器显示会对不上。

## 版本号与更新日志

用语义化版本，但含义要对玩家有用：

- `0.1.x` —— 开发中，随时可能坏档
- `1.0.0` —— 首个可完整游玩的版本
- `1.x.0` —— 新增内容
- `1.0.x` —— 修 bug

`CHANGELOG.md` 至少写三类：新增、修复、**不兼容变更**（玩家最关心这个，尤其是"旧存档还能不能用"）。

## 发布前检查清单

- [ ] `kiant_hoi4_validate_mod` 报 0 error
- [ ] `error.log` 没有本 mod 相关的新错误
- [ ] 全新开局能正常进入，不崩
- [ ] 关键内容实际可达（国策点得到、事件触发得到、决议点得动）
- [ ] 本地化：界面无键名、无乱码
- [ ] `supported_version` 与当前版本匹配
- [ ] 两个描述文件的 `name` / `version` 一致
- [ ] 无 `replace_path`（除非确实做 total conversion 且已在说明里写明）
- [ ] 卸载后原版存档能正常加载（不残留依赖）
- [ ] README 写清加载顺序要求与已知冲突
