# 工程解剖：Kaiserreich 官方仓库与 GFX 素材包

## 1. 先回答版本问题：官方仓 = 工坊最新发布

仓库 HEAD（2026-10-27「normalise filename case」）与 Steam 工坊
`time_updated` **同日**；逐层对比：五目录文件清单 diff=0、全目录 md5 一致、
抽样 10 文件 9 个 SAME——唯一 DIFF 是 descriptor.mod（git 版多
`path = "mod/Kaiserreich"`，属打包差异）。**此前对工坊 KR 的深读
（focus-tree/events/branching/portraits）就是当前权威内容**，无需重读。

## 2. 收录：KR 仓库的四个权威参照

### 2.1 descriptor.mod 的 57 条 replace_path

全量重制型 mod 的 replace_path 完整参考清单（common/abilities…events、
gfx/loadingscreens|flags|leaders、history/*、map/strategicregions|
supplyareas、portraits、tests），另有 `remote_file_id = "1521695605"`
把仓库与工坊绑定、`supported_version="1.19.4.*"`——比 BICE 66 条更精简
的「全重制最小集」。

### 2.2 portraits/ 的人物立绘组织（19 文件实证）

- `portraits/00_portraits.txt`（3394 行）= default 兜底池 + 按 `continent`
  的通用池；结构 default → army/navy/political（按意识形态分组）→
  male/female 池；
- 18 个分文化圈文件按「### 注释头 + 国家 TAG 分块」（germany 681 行，
  GER 与傀儡 GRU 复用同一池；serbian 仅 14 行）；池内可用 `#` 注释单张下架；
- 特殊池单列：operatives 1649 行、scientists 1574 行。

### 2.3 interface 两层注册制 + 64 个 0 字节 .gfx

- 451 .gfx + 217 .gui，**两层制**：根层放 vanilla 同名覆盖，其中
  **64 个 0 字节 .gfx（DLC 名文件）是「空文件清除 vanilla sprite 注册」
  技法**（与 RT56 integrated_dlc 空文件关闭同一思路的 KR 版）；
- `interface/kaiserreich/` 96 文件放自有注册；**1 gfx 对 1 gui 配对注释**：
  `countrypoliticsview.gfx:3` "## Defines custom textures used by
  countrypoliticsview.gui"——机器可读的 gfx↔gui 绑定（对照 RT56 的
  `#!gfx:` 协议，社区两种写法）；
- `event_pictures.gfx`（16649 行）头注 "generated by the photoshop script"，
  约定 spriteType.name == texturefile 基名；事件图全 PNG；
- alerts.gfx 用 corneredTileSpriteType（size+borderSize+effectFile 指向
  原版 gfx/FX/*.lua）；条纹帧 noOfFrames=2/3。

### 2.4 common/ 与全仓约定

- `00_<域>_<类型>.txt` 引擎层 → `01_<区域> effects.txt` → `TAG effects
  (Country).txt` 每国一文件（约 150 国，遗留文件带 ", legacy" 标注）；
- history/countries 为 `TAG - Country Name.txt`（258 国，含
  "AAA - SYSTEM.txt" 占位）；
- localisation/english/ 内再分 {KR_common, KR_country_specific,
  KR_factions} 三命名空间子目录，play_in_english 十语种回退提示，
  KR_submod_triggers/<10 语言>/ 子模触发器 loc；
- **Lua 定论**：全树仅 2 个 .lua（defines），每条覆盖行内注释
  "Vanilla is X"——KR 无 CI 无脚本化 Lua，版本管理 = git tag（1.7/1.7a…）；
- `.gitattributes`：txt/yml/gui/gfx/lua/mod=CRLF，png/tga/dds/mesh= binary；
- `tests/_documentation.info`：1.9+ 原生 test bundle 行为测试
  （与 BICE/KR 前轮发现互证）。

## 4. 借鉴（单点）

- **Globvs/Ultimate-HOI4-GFX**（239★，**2019-08 停更 7 年**）：按纪律舍弃为
  规格来源，留作素材/模板清单——739 文件 = 589 个 Focus&NS Pieces（平铺、
  空格命名、数字后缀成系列）+ 82 Focus Backgrounds + 19 PSD Smart Objects
  （旗帜拖盾徽模板）+ 7 Portrait Templates；**无 .gfx 注册模板、无尺寸文档**，
  命名（空格+无 GFX_ 前缀）反而是 gfx 校验器的命名反例素材；
- **Economic-Crisis/Public-releases**：唯一可借 `.github/workflows/main.yml`
  ——`on: push tags v*` → zip-release 打包（exclusions）→ GitHub Release
  的 **mod 发版自动化模板**（可荐给本插件用户的发布流程）。

## 5. 舍弃（理由在案）

| 仓库 | 理由 |
|---|---|
| inkitter/HOI4_mod（83MB，35★） | 内容面向 1.3.3 时代；独家点仅 `$1安装.bat`（reg query 找文档目录 + mklink /j 虚拟链接），属分发手段非 modding 技法 |
| skullbe 两个翻译仓 | 2020/2019 停更，纯 loc（yml+术语表），无组织创新 |
| Economic-Crisis 主体 | 2023-02 停更 3.7 年、1.4GB 两次克隆断流，除发版工作流外无 modding 技法 |

## 6. 对本插件的行动结论

1. gfx 校验器新增**尺寸档位知识**（focus 100×88 / 新闻图 397×153 / idea
   60×68 / 决议 40×40；偏离 warn 不 error）——数据源 KR+原版实测；

   64 个 0 字节 .gfx 证明「空文件」是合法覆盖语义，覆盖校验不得把
   空文件当错误；

   的进阶节（待下轮）；
