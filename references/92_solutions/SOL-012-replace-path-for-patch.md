# SOL-012 用 replace_path 实现「只改几项」

## 它想解决什么

想改原版某几项内容，但同名文件覆盖好像"不可靠"。看到 `replace_path` 这个字段，觉得它更"强力"，能确保自己的改动生效。

## 思路

```ini
# .mod 文件
replace_path = "common/ideas"
```

然后把自己的 `common/ideas/germany.txt` 放进 mod。以为这样"原版那个文件被我的替换了"。

## 为什么没被采用

**`replace_path` 是整目录替换，不是单文件替换，更不是合并。**

用了 `replace_path = "common/ideas"` 之后：
- 原版 `common/ideas/` 下**所有文件全部消失**
- 只剩你放进去的

后果：原版所有国家（苏联、美国、英国……）的 ideas 全没了。游戏可能仍能启动，但大量内容缺失，且**未必报错**（静默失败，见 EB-009）。

如果只复制了原版德国那一段，其余国家的 ideas 就真的没了。

## 如果要用，怎么验证

**机制已确认，不需要验证。** 但值得验证的是「怎么正确实现只改几项」：

正确做法有两个：

**方案 A（推荐）：同 ID 覆盖单个块**

新建文件，只写你要改的那个 idea，用相同 ID。引擎按 ID 合并，原版其他内容不受影响。

**方案 B：同名文件覆盖**

复制原版**整个文件**，改其中几行，放同路径。这样原版该文件的全部内容都在，只有你改的几行不同。

## 备注

**这条坑的根源是名字的误导性。** "replace_path" 里的 replace 确实说了会替换，但直觉上容易理解成"替换我想替换的部分"，实际是"替换整个路径"。

判断你当前是否踩了坑：**如果游戏能启动但有些原版内容不见了，且 error.log 没有对应报错，先查 replace_path。**

一个安全的检查习惯：`.mod` 里每加一行 `replace_path`，问自己一句："这个目录下原版还有什么我需要的？" 答不上来就别加。

`kiant_hoi4_list_overrides` 会读取 `replace_path` 并标出影响范围，可以用来复核。
