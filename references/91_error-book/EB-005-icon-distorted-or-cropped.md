# EB-005 图标被拉伸、偏左、被裁

## 症状

自制的科技/装备图标在游戏里：被拉长或压扁、内容偏在左边、边缘被切掉、出现白底或棋盘格背景。

## 错误做法（我试过的）

1. 以为是 `.gfx` 里 sprite 定义写错，反复调参数 → 参数没问题，是图本身不对
2. 以为随便什么尺寸都能用，出图后再看效果 → 每次都要重来
3. 用九宫格参数去调普通图标 → 九宫格只适用于特定 UI 元素，图标不适用

## 根因

四个独立原因，症状相似：

| 根因 | 表现 |
|---|---|
| **出图尺寸与槽位不符** | 拉伸或压扁。科技图标、国策图标、装备图标各有固定尺寸与比例 |
| **非 2 的幂尺寸** | DDS 某些格式要求宽高为 2 的幂，不满足时被裁或异常 |
| **DDS 头信息不对** | 偏左、被裁、颜色异常 |
| **背景没去干净** | 白底或棋盘格（截图来源的常见问题） |

## 标准化方案

1. **先确认目标槽位尺寸。** 读 `05_presentation/gfx-sprites.md` 的尺寸表，不要猜。

2. 按目标尺寸出图，保持原始比例（留白优于拉伸）。

3. 转 DDS 时注意：

```bash
# 参考 05_presentation/dds.md 的格式要求
# 常见：DXT5 带 alpha，尺寸为 2 的幂
```

4. 去背要点（来自真实批量产出经验）：

- 白底图：直接按白色阈值抠
- 棋盘格（透明被截成灰白格）：不能用白色阈值，要先识别格纹
- 白涂装物体（如白色涂装坦克）：**不能按白色阈值抠，会把主体一起抠掉**。要先用边缘检测或手动遮罩

## 预防

- 出图前先建尺寸对照表，批量处理时统一尺寸
- 批量跑完抽样检查 3-5 张，不要全部做完才发现尺寸错了

## 验证

游戏内看图标：不变形、内容居中、无背景残留。

## 备注

**「白涂装」这一类是最容易翻车的**：批量脚本按白色抠图，遇到白色主体就废了。真实案例见 `90_case-studies/icon-pipeline-tech-card.md`，那里记录了别名表消歧和卡片预览自检的做法。
