# EB-002 中文全部显示为 ???? 或方框

## 症状

中文 mod 进游戏后，所有汉字显示成 `????`，或者显示成空方框。英文、数字正常。

## 错误做法（我试过的）

1. **以为 `.fnt` 缺字形**，于是想自己生成一份包含汉字的 bitmap font → 方向完全错了。原版 `gfx/fonts/chinese/*.fnt` 自带 **7,677–8,002 个字形**，字库是够的
2. 以为是 `.yml` 编码问题，反复转 UTF-8 → 编码本来是对的（能显示问号说明文本已正确读入）
3. 把 `.fnt` 从原版目录整个复制进 mod → 无效，甚至更糟

## 根因

**不是字形缺失，是字体名与字重的映射关系错了。**

游戏通过 `gfx/fonts/fonts.gfx`（或等价声明）把逻辑字体名（如 `hoi4_16`）映射到具体的 `.fnt` 文件。中文分片有独立的映射表。当界面元素请求的字体名没有映射到中文分片时，引擎就拿不到汉字字形，退化显示 `?`。

判断依据：**问号的数量与汉字数量一一对应**，说明文本正确、字库足够，只是取字失败。

## 标准化方案

1. 先列出当前被映射到中文分片的字体名：

```bash
# MCP: 参考 07_tools/font.md 的 font list 语义
# 手工：查字体映射声明
grep -rn "chinese" interface/*.gfx gfx/fonts/*.gfx 2>/dev/null
```

2. 确认你界面上出问题的那处，用的是哪个字体名。查 `.gui` 文件里该元素的 `font = "..."`。

3. 把该字体名加入中文映射，或改用已映射的字体名。

4. 读 `05_presentation/fonts-cjk.md` 拿完整映射表——这是本库对该问题唯一权威来源。

## 预防

- 新写 GUI 时，字体名从现成能正常显示中文的元素上抄，不要自己造
- 改字体前先看 `05_presentation/fonts-cjk.md`，不要凭"字体文件应该有汉字"的直觉动手

## 验证

改完进游戏看目标文本。判据：
- 正常：显示汉字
- 仍异常：`?` 数量变化说明映射部分生效，检查是否还有一层回退

## 备注

**这条坑的典型特征是「越修越远」**：一旦认定是字库问题，就会去折腾字体生成工具，花几个小时做无用功。真正的判断点为「问号是否与汉字数一一对应」——是则字库无问题。
