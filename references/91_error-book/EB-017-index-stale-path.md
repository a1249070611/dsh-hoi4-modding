# EB-017 索引里查不到刚写的文件

## 症状

两种表现，同一个原因：

1. **刚写好或刚改完的文件，用 `kb_search` / `kb_lookup` 搜不到。** 或者搜到的还是改之前的内容。
2. **把 mod 目录挪了位置或改了名之后，原来能查到的东西全查不到了。** `kb_stats` 里显示的源路径是你已经不用的旧路径。

## 先分清两种情况

**你的 mod 本来就不在索引范围里。** 索引默认只收三样：原版游戏、这个插件的参考库、你自己的笔记。第三方 mod 和你自己正在写的 mod **默认不收**——一台装了五十个工坊 mod 的机器会把首次索引拖到几十分钟，而且半成品和改坏的包会把检索结果弄脏。

想让自己的 mod 进索引，得显式说：

```
kiant_hoi4_kb_build  include_mods=true
```

如果你要搜的内容在这个范围之外，那不是索引坏了，是你没让它进来。

**改动之后没重建索引。** 索引是一份快照，不是实时视图。你刚写的文件、刚挪的目录，索引都不知道。这种情况下重建一次就对了。

## 怎么处理

**不要跑全量重建。** 全量会连原版一起重新扫，那是几万个文件。只重建需要的那部分：

```
kiant_hoi4_kb_build  only=notes,refs  skip_game=true
```

几秒就跑完，比全量快两个数量级。

挪过整个项目目录的，重建后用 `kiant_hoi4_kb_stats` 看一眼 `source` 列，确认路径是现在的实际路径，不是旧的。

## 为什么挪目录尤其容易出问题

索引里记的是绝对路径。文件系统变了，索引里的记录不会跟着变——索引没有任何办法知道你换了位置。改了目录名之后必须手动重建，这不是 bug，是必然。

## 预防

- **改完 mod 内容要搜之前，先确认这次改动进没进索引。** 索引不自动跟随文件变化
- **尽量别随便挪 mod 目录。** 挪一次要重建一次
- **查不到东西时，先看 `kb_stats` 里的源路径和篇数**，再怀疑是不是检索本身有问题。路径就是旧的时候，往下查都是白费力气

## 验证

1. `kb_stats` 的源路径是当前实际路径
2. 用一个只存在于新位置的独有关键词搜，能搜到

## 备注

索引为什么会存绝对路径、重建逻辑怎么写的，属于插件维护范围，记在 `99_plugin-devlog/DEVN-010`。写 mod 不需要读。

记住一条就够：**搜不到时先看索引的路径和篇数，别急着换关键词。** 路径是旧的时候，换多少个词都没用。
