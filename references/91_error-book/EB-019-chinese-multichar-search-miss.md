# EB-019 中文搜不到东西

## 症状

用中文查知识库，结果有三种反常：

**一种是没有结果。** 两个字的词能查到，四个字以上就归零。而且不报错，返回的就是「没找到」，你会以为文档里没写这件事。

**一种是查到的全是无关的。** 你问「为什么我的国策树连线重叠了」，返回的第一条是错题本的目录页，因为目录页里「为什么」出现得最多。你最想要的那篇讲坐标的文章排在很后面，或者根本不在首页。

**一种是查到了不该查到的。** 你问「国策树坐标怎么设置」，第一条恰恰是正在讲这个检索问题的那篇错题本，而不是讲国策树坐标怎么写的正文。

三种表现都不是文档缺失，是查法的问题。

## 一个立刻能用的改法

**把关键词用空格分开，别把整句话丢进去。**

```
❌ 为什么我的国策树连线重叠了
✅ 国策树 连线

❌ 国策树坐标怎么设置
✅ 国策树 坐标
```

实测对比，同一个问题两种问法，命中位置完全不同：

| 你输入 | 首条命中 | 是不是你要的 |
|---|---|---|
| `国策树坐标怎么设置` | 讲检索问题的那篇错题本 | 不是 |
| `国策树 坐标` | `02_content/focus-trees.md` | 是 |

原因很直接：中文不写空格，整串会被当成一个短语，要求这几个字在原文里**逐字相邻**地出现。而「为什么我的国策树连线重叠了」这句话，语料里几乎不可能一字不差地出现过。于是系统退而求其次去匹配零散片段，最常见的虚词（的、了、为什么、怎么）就把排序带偏了。

## 正确的查法

1. **只留名词和术语，去掉疑问词和语气词。** 「怎么办」「为什么」「如何」对定位没有任何帮助，只会增加噪音。
2. **想不起来术语时，先查这个错误本身。** 错题本第 1 节是症状速查表，按你**看到的现象**找（「国策树连线重叠」比「国策树怎么画」更容易命中）。
3. **一次查不到就换词，别换句式。** 换个说法（「国策的坐标」「树形坐标」）往往不如换个更短的术语。
4. **实在查不到，用 grep 直接在文件里搜。** 知识库检索没结果不等于文档里没写。

## 预防

- **先查症状，再查术语。** 你手上一定有现象（图标被拉伸、事件不触发、连线看不见），这比「这个功能怎么写」更好定位
- **别指望用一句话就问出答案。** 检索不是问答，它只认词

## 验证

改完用这几组测，都能命中正文而不是目录页：

```
国策树 坐标          → 02_content/focus-trees.md
本地化 编码          → 05_presentation/localisation.md
加载顺序 覆盖        → 00_start/load-order-and-override.md
```

如果这几组能命中，说明你的查法是对的。还是查不到再看 `EB-017`（索引里的路径是不是旧的）。

## 备注

检索分词为什么这么实现、2 字滑窗和 3 字滑窗的取舍，属于插件维护范围，记在 `99_plugin-devlog/`。写 mod 不需要读。

**记住一句：检索只认词，不认句子。** 把「为什么我的 X 坏了怎么办」压成「X 症状」两个词，命中率立刻不一样。
