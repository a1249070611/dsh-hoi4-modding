# EB-021 离线预览的国策树位置全乱

## 症状

用 `kiant_hoi4_preview` 生成的国策树 HTML 里，布局是乱的：本该分行的国策挤在
同一行，本该左右分开的叠在一起，前置连线横穿整个画布。

但游戏里看是正常的。

## 先分清是哪一边出错

这一点很重要，别改错东西。

**只有预览乱，游戏里正常**：预览工具的坐标解算有问题，你的 mod 没毛病。
这不是你的问题，但在工具修好之前，预览图不能用来判断布局。

**游戏里也乱**：你的 mod 有问题，看 `EB-004`。

区分方法很简单，进游戏打开国策树看一眼。花两分钟，能省下半小时的错误修改。

## 为什么预览会乱

HOI4 的国策 `x` / `y` 不是绝对坐标。写了 `relative_position_id` 的时候，
这两个数字是相对于锚点国策的偏移量。

原版里几乎没有国策用绝对坐标：

```
common/national_focus/ 75 个文件
10625 个国策，10984 处 relative_position_id（103%）
germany.txt：438 个国策，436 个带锚点（99.5%）
```

工具若把偏移量当绝对坐标画，位置就全错了。德国那棵树锚点链最深 12 层，
算错之后图上横跨的宽度会差 60%。

## 你能做什么

1. **先确认不是自己写错了。** 进游戏看国策树，正常就说明是工具的问题
2. **不要为了迁就预览图去改坐标。** 把 `relative_position_id` 删掉换成绝对坐标，
   预览是好看了，游戏里的树可能就散了
3. 判断布局对不对，进游戏看，或者拿原版国策树截图对照

## 判断自己的坐标写得对不对

如果你的国策确实有布局问题，查这几条：

- 同一个 `y` 层上，`x` 不能重叠
- 用了 `relative_position_id` 时，锚点国策必须存在，且在同一棵树里
- 锚点不能成环（A 相对 B，B 相对 A）

链式锚点是合法的，而且很常见：A 相对 B，B 相对 C。算位置时要把整条链累加起来。

## 预防

写完国策树先跑一次预览，看节点有没有明显重叠。有重叠不一定是你的错，
但值得进游戏确认一次。

原版 `china_warlord_sea.txt` 就是个反例：它把 SIK / XSM / SIC / YUN 几个军阀的
国策塞进同一棵树，故意让它们从相同格子起步，形成视觉重叠。那是设计，不是 bug。
