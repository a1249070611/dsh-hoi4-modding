# EB-004 国策树连线重叠、错位

## 症状

国策树里，本该从 A 连到 B 的线画到了别处；或者两条线叠在一起看不清；或者线的起点终点位置偏移了几格。

## 错误做法（我试过的）

1. 以为是 `x`/`y` 坐标写错了，逐个调数字 → 调到哪都不对，因为问题不在单个坐标
2. 以为是 GUI 的 gridbox 尺寸不对 → 改 gridbox 影响所有元素，反而更乱
3. 用大数值拉开间距"避免重叠" → 布局变得极度稀疏，还是错位

## 根因

国策坐标是**相对定位**，且有层级：

| 情况 | 机制 |
|---|---|
| `relative_position_id` 使用不当 | 子国策的坐标是相对父节点算的，父节点挪了子节点跟着挪 |
| 同一 `x`/`y` 上有多个国策 | 直接重叠，引擎不做自动避让 |
| 连线交叉 | 引擎按 `prerequisite` 画直线，不绕行。结构本身有环或跨层就会交叉 |
| `x` 跨度过大 | 超过网格宽度后换行逻辑出错 |

## 标准化方案

```bash
# 1. 用离线预览直接看布局，不用进游戏
#    MCP: kiant_hoi4_preview
#    按真实 x/y 坐标渲染并画出前置连线
```

2. 从预览里定位问题节点，读 `02_content/focus-trees.md` 的坐标规则章节。

3. 按规则重排：

- 同层同 `y`，`x` 递增（通常步长固定）
- 用 `relative_position_id` 时，确保父节点先定义
- 避免 `x` 跨度过大，必要时拆成多页

## 预防

- 写国策时用 `kiant_hoi4_preview` 边写边看，不要攒到最后
- 保持 `x`/`y` 的规律性（同层同 y），异常值一眼能看出来

## 验证

`preview` 渲染出来连线不重叠、起止点对齐即为通过。

## 备注

**用预览，不要用游戏验证布局。** 进游戏看布局的循环是「改 → 启动 → 加载 → 看」几分钟一次，预览是秒级。布局类问题全部应该在预览阶段解决。
